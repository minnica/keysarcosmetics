## Backend reutilizado/refactor

No fue necesario cambiar backend, Prisma, migraciones, API client ni tipos compartidos. Se reutilizaron:

- `POST /api/pos/authorizations`: resuelve el código sin alias cuando la superficie aprobada sólo muestra código; verifica huella HMAC/bcrypt y delegación nominal, y liga el token a sesión/terminal/propósito/entidad.
- `POST /api/pos/auth/verify`: consume el token usado únicamente para validar el desbloqueo visible.
- `PUT /api/pos/expenses/:id`: consume una autorización `CASH_EXPENSE_EDIT`, anula el original mediante compensación y crea el reemplazo con snapshots/trazabilidad dentro de la operación idempotente.
- `POST /api/pos/expenses/:id/void`: consume `CASH_EXPENSE_VOID`, registra la compensación y conserva auditoría.
- `consumeOperationAuthorization`: mantiene tokens cortos, de un solo uso, ligados a sesión, terminal, propósito y gasto.

No se cambió `REGISTRO MOCK · CASH MANAGER` ni otro texto cubierto por B01. No se atribuye aprobación nueva al PO.
