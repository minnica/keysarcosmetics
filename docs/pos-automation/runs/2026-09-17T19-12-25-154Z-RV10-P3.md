## Guardas y manejo de secretos

El helper falla antes de leer credenciales o mutar cuando no se cumplen sus condiciones:

1. `POS_TERMINAL_CONFIRMATION=LOCAL_SYNTHETIC_ONLY`.
2. `POS_TERMINAL_DATASET_ID` explícito, válido y coincidente con el dataset fuente.
3. `POS_TERMINAL_API_URL` usa `http` y `127.0.0.1`, `localhost` o `::1`, sin credenciales, ruta, parámetros ni redirecciones.
4. Los archivos fuente y destino se resuelven dentro de `.pos-runner/`, incluido el directorio real para bloquear escapes mediante enlaces simbólicos.
5. El archivo fuente y su directorio no permiten acceso de grupo/otros; el destino sólo se crea en un directorio privado.
6. El destino se escribe con `flag=wx` y modo `0600`; una ejecución no sobreescribe ni imprime el secreto existente.

La primera alta guarda inmediatamente el secreto que el API sólo entrega una vez. Si una alta previa existiera sin archivo local, `provision` rota mediante la ruta canónica y guarda el nuevo valor. Si terminal y archivo ya existen, la reentrada no rota el secreto. El helper sólo emite resúmenes sin alias, PIN, contraseña, JWT, token de autorización o secreto de terminal.

## Comandos para continuar

En el entorno autorizado, usar un state dir y una terminal distintos. Nunca copiar los valores a la línea de comandos documentada; cargarlos desde el mecanismo privado del ambiente:

```bash
POS_TERMINAL_CONFIRMATION=LOCAL_SYNTHETIC_ONLY \
POS_TERMINAL_DATASET_ID=<dataset-autorizado> \
POS_TERMINAL_API_URL=http://127.0.0.1:<puerto-api> \
POS_TERMINAL_SOURCE_CREDENTIALS_FILE="$PWD/.pos-runner/<estado>/credentials.json" \
POS_TERMINAL_OUTPUT_FILE="$PWD/.pos-runner/<estado>/terminal.json" \
pnpm --dir backend/api exec tsx scripts/provision-pos-terminal-local.ts provision

# Repite las mismas variables con la acción verify.
```

Después, cargar `POS_TERMINAL_CODE` y `POS_TERMINAL_SECRET` desde el almacén privado del equipo objetivo antes de iniciar Electron. No versionar `.env`, JSON de estado ni capturas que contengan accesos.
