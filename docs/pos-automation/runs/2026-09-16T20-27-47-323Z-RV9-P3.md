## Cómo repetir

Crear manualmente tres bases PostgreSQL 16 locales, distintas y vacías, cuyo nombre incluya `pos_upgrade`. Generar el secreto localmente y no registrarlo en el shell history ni en documentación. Con clientes PostgreSQL nativos:

```bash
POS_MIGRATION_SOURCE_DATABASE_URL='<loopback-source>' \
POS_MIGRATION_TARGET_DATABASE_URL='<loopback-target>' \
POS_MIGRATION_RECOVERY_DATABASE_URL='<loopback-recovery>' \
POS_MIGRATION_FIXTURE_CONFIRMATION=EPHEMERAL_ONLY \
scripts/verify-pos-migration-recovery.sh
```

Si el host no tiene `pg_dump`, `pg_restore` y `psql`, indicar además un contenedor PostgreSQL 16 local ya iniciado que contenga esas tres bases:

```bash
POS_MIGRATION_POSTGRES_CONTAINER='<contenedor-local-dedicado>' \
POS_MIGRATION_SOURCE_DATABASE_URL='<loopback-source>' \
POS_MIGRATION_TARGET_DATABASE_URL='<loopback-target>' \
POS_MIGRATION_RECOVERY_DATABASE_URL='<loopback-recovery>' \
POS_MIGRATION_FIXTURE_CONFIRMATION=EPHEMERAL_ONLY \
scripts/verify-pos-migration-recovery.sh
```

El script se detiene si alguna base ya contiene tablas. Preparar destinos nuevos para cada repetición; no borrar datos para forzar el gate.
