## Resultado

la revisión visual con el recorrido funcional. El modo visual queda identificado
como fixture aislado: puede revisar presentación, navegación y formularios, pero
no acredita llamadas al API, persistencia o autorizaciones reales. El modo
funcional queda explícitamente condicionado a una API/BD sintética autorizada,
SHA coincidente, CORS, terminal activa, canal privado y credenciales personales;
sin esos elementos la guía y el prompt indican detener ese modo.

El candidato ejecutable se fijó en
`06f9f6f7741b733bda7770e3b67b714daa59a40b`. Las instrucciones aceptan que el
HEAD publicado después incluya este checkpoint documental, pero exigen que no
haya cambios posteriores en POS, API, contratos compartidos, manifests o
lockfile. `db58fda` se documenta como ancestro y origen de la comparación final
histórica, no como HEAD vigente ni como evidencia automática del candidato
actual.

El resultado es parcial. El material documental ya permite preparar y registrar
la revisión sin exponer secretos, pero el criterio completo exige reproducir
ambas revisiones desde otro equipo. No están disponibles el Windows objetivo,
una API accesible desde él, terminal/canal reales ni acceso del PO. Tampoco se
ejecutó una nueva matriz completa contra `06f9f6f`; desde `db58fda` existen
cambios funcionales en diez archivos del renderer. RV10-P7 permanece `[ ]`.
